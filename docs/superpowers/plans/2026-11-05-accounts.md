# Accounts (Supabase, step 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional Songies accounts on Supabase: sign up / confirm with a code / log in / reset password with a code / log out / delete, plus a username and profile picture, shown in Settings and the desktop top bar.

**Architecture:** SQL migrations in `supabase/migrations/` set up `profiles`, the `avatars` bucket, row-level security, a sign-up trigger and two functions. In the app, a thin `AccountBackend` interface wraps `supabase_flutter` (so logic is testable with a fake), an `AccountService` owns the flows and exposes an `AccountState` stream, and the UI (Settings → Account, auth screens, top-bar avatar) reads it through Riverpod. The session is persisted in the system keyring.

**Tech Stack:** Flutter, `supabase_flutter` (current stable 2.x), existing `flutter_secure_storage`, `image`, `file_picker`, islands, Riverpod.

**Spec:** `docs/superpowers/specs/2026-11-05-accounts-design.md`

### Task 1: Supabase schema and setup docs

**Files:**
- Create: `supabase/migrations/20261105120000_accounts.sql`
- Create: `docs/supabase.md`
- Modify: `docs/manual-test-checklist.md` (an "Accounts" section)

**Interfaces:**
- Produces (used by Task 2 through `AccountBackend`):
  - table `public.profiles(id uuid primary key references auth.users on delete cascade, username text not null, avatar_path text, created_at timestamptz default now(), updated_at timestamptz default now())`, unique index on `lower(username)`, check constraint for the username rule.
  - RLS: select for `authenticated`; insert/update only `id = auth.uid()`; no delete policy.
  - trigger `on auth.users after insert` → insert profile from `new.raw_user_meta_data->>'username'` (lowercased); a duplicate raises a unique violation, failing the sign-up.
  - `public.username_available(name text) returns boolean` — `security definer`, `stable`, granted to `anon, authenticated`; true when the name passes the rule and no profile has it (case-insensitive).
  - `public.delete_my_account() returns void` — `security definer`, granted to `authenticated` only; deletes `auth.users where id = auth.uid()`.
  - storage bucket `avatars` (public); policies: insert/update/delete on `storage.objects` only where `bucket_id = 'avatars' and (storage.foldername(name))[1] = auth.uid()::text`.
  - `updated_at` maintained by a trigger.
- All `security definer` functions set `search_path = ''` and qualify names.

**`docs/supabase.md` covers (plain numbered steps):** apply the migration (Supabase CLI `supabase link` + `supabase db push`, or paste into SQL editor); Authentication → Providers → Email: confirm email on, minimum password 8; Authentication → Email templates: "Confirm signup" and "Reset password" bodies showing `{{ .Token }}` (give the exact template text); OTP expiry 3600 s; note the free-tier email rate limit and the 7-day pause; where to find URL/publishable key; never put the service-role key in the app.

**Interfaces:**
- Produces:
  - `String? usernameProblem(String name)` → null when valid, else the hint copy; `String normalizeUsername(String)` (trim + lowercase).
  - `Uint8List avatarJpeg(Uint8List imageBytes)` — centre square crop, 256×256, JPEG q85; throws `FormatException` on undecodable input.
  - `class Profile { final String id, username, email; final String? avatarUrl; }`
  - `sealed class AccountState` → `SignedOut`, `SignedIn(Profile profile)`.
  - `enum AccountError { wrongCredentials, emailTaken, usernameTaken, usernameJustTaken, badCode, emailNotConfirmed, offline, unknown }` with `String message` giving the exact copy.
  - `abstract class AccountBackend` — `Stream<String?> userIdChanges` (null = signed out), `signUp(email, password, username)`, `verifySignup(email, code)`, `resendSignup(email)`, `logIn(email, password)`, `sendReset(email)`, `resetPassword(email, code, newPassword)`, `logOut()`, `usernameAvailable(name)`, `loadProfile(id)`, `updateUsername(id, name)`, `uploadAvatar(id, path, bytes)`, `setAvatarPath(id, path?)`, `deleteAvatarFiles(id)`, `deleteMyAccount()`; maps Supabase/Postgrest/HTTP errors to `AccountError` (thrown as `AccountException(AccountError)`).
  - `class AccountService { AccountService(AccountBackend b); Stream<AccountState> get states; AccountState get state; ...same flows... }` — `signUp` returns `needsCode`; `logIn` maps `emailNotConfirmed` to a code step; `changeAvatar(bytes)` does: jpeg → upload new → setAvatarPath → delete old (ignore delete failure); `removeAvatar()`; `deleteAccount()` deletes files then rpc then signs out.
  - `class SecureSessionStorage extends LocalStorage` (supabase_flutter) using `flutter_secure_storage`; falls back to memory with `AppLog.w` when unavailable.
