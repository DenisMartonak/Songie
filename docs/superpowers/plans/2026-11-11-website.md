# Songies Website (SON-22) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Pages site for Songies (home page, room invite page, features page) in `website/`, room links switched to `https://denismartonak.github.io/Songie/r/<CODE>`, and a script that records showcase clips of the real Linux app.

**Architecture:** Plain static files (HTML, CSS, vanilla ES modules, no build step) deployed by a GitHub Actions workflow. Pure logic (device → download, path → room code) lives in small ES modules tested with `node --test`. The showcase is rendered from a manifest the capture script writes. The capture script is a Flutter integration test that boots the real app through a new `runSongies()` entry point (with test overrides), seeds a demo library, drives scenes with `WidgetTester`, grabs frames from the root render layer, and hands raw frames to ffmpeg.

**Tech Stack:** HTML/CSS/JS (ES2022 modules), Node 26 (`node --test`) for site tests, GitHub Actions (`actions/configure-pages@v5`, `actions/upload-pages-artifact@v3`, `actions/deploy-pages@v4`), Flutter (`~/development/flutter/bin/flutter`) with `integration_test`, ffmpeg (`libvpx-vp9`, `libopenh264`, `libwebp` available).

**Spec:** `docs/superpowers/specs/2026-11-11-website-design.md`

## Global Constraints

- Site address: `https://denismartonak.github.io/Songie/`; room links `https://denismartonak.github.io/Songie/r/<CODE>`.
- Room code alphabet `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, 8 chars, dashes/spaces ignored, case-insensitive; shown as `ABCD-2345`.
- App scheme handed off to: `songies://room/<CODE>` (unchanged in the app).
- Colours: gradient `#7C3AED → #EC4899`; stage background `radial-gradient(#2a0f45 → #0b0612)`. The S is the exact `d` from `assets/icon/songies_icon.svg` (viewBox 1024, stroke-width 78, round caps).
- Copy fixed by the spec: "You've been invited to listen together"; "Open Songies"; "Don't have Songies yet?"; "All downloads"; "Download for Android" / "Download for Windows" / "Download for Linux"; bottom-right "Android · Windows · Linux"; footer "For educational purposes only".
- GitHub: repo `https://github.com/DenisMartonak/Songie`; releases API `https://api.github.com/repos/DenisMartonak/Songie/releases/latest`; fallback `https://github.com/DenisMartonak/Songie/releases/latest`. Asset names: `songies-X.Y.Z.apk`, `songies-X.Y.Z-windows-setup.exe`, `songies-X.Y.Z-x86_64.AppImage`.
- No server, analytics, cookies or trackers. External resources only Google Fonts.
- `prefers-reduced-motion: reduce` → S fully drawn, no rings, no autoplaying video (show poster).
- Phone width works with no horizontal scroll.
- No app release in this work (user's decision); stop at merged `main`.
- Capture never touches the user's data: throwaway `XDG_DATA_HOME`, signed out of Songies account and YouTube, no cloud sync.
- Use the `frontend-design:frontend-design` skill for Tasks 3–5. The mockup `.superpowers/brainstorm/241909-1794403437/content/home-direction.html` (option A) is the reference for feel.
- Work on branch `website`. Move SON-22 to In Progress at start, In Review when the branch is ready.

## Review Focus

1. A Discord link with a query or trailing slash (`/Songie/r/abcd-2345/?utm=x`) must still open room `ABCD2345` → covered in Task 2 tests.
2. Android user agents contain "Linux"; they must get the APK, never the AppImage → Task 2 test.
3. GitHub API down/rate-limited (60 req/h per IP) or a release missing an asset → button stays a working "All downloads" link → Task 2 tests (`null` release, missing asset).
4. Visiting `/Songie/r/` or `/Songie/r/NOTACODE` or any other unknown path must show a sensible page, not a blank one → Task 4 verification.
5. The capture run picking up the real user's data or session → Task 8 guard test that aborts when `XDG_DATA_HOME` isn't the throwaway dir, and a check that the account is signed out before any scene.

### Task 8: Capture harness and the Themes scene

**Files:**
- Modify: `pubspec.yaml` (dev_dependency `integration_test: {sdk: flutter}`)
- Create: `integration_test/showcase/showcase_test.dart`, `integration_test/showcase/recorder.dart`, `integration_test/showcase/demo_library.dart`, `integration_test/showcase/covers/*.jpg` (3–4 abstract gradient/pattern covers generated for this, e.g. with Python Pillow or ImageMagick — no copyrighted art), `tool/showcase.sh`

**Interfaces:**
- Consumes: `runSongies` (Task 7), `imagePickerProvider` (`lib/ui/library/pickers.dart`), `LibraryRepository.createPlaylist/addTracks/setPlaylistCover`, `YtTrackStore.upsert(YtmSong)`, `accountServiceProvider`.
- Produces:
  - `FrameRecorder.start(String sceneId, {int fps = 30})` / `Future<void> stop()` — samples the root render view's layer (`RenderView.debugLayer` as `OffsetLayer`, `toImage` at devicePixelRatio 1) on a periodic timer, writes raw RGBA frames to `<SHOWCASE_OUT>/<scene>/frames.rgba` plus `meta.json` (`{width,height,fps,frames}`); duplicates the last frame when a capture falls behind so wall-clock timing is kept. `FrameRecorder.shot(String sceneId, String name)` writes one PNG.
  - `seedDemoLibrary(ProviderContainer c) → Future<DemoLibrary>` — upserts the pinned songs, creates 3 playlists with covers, returns ids.
  - `tool/showcase.sh` — creates `mktemp -d` data dir, runs `XDG_DATA_HOME=$tmp SHOWCASE_OUT=$out flutter test integration_test/showcase/showcase_test.dart -d linux`, then per scene ffmpeg: `-f rawvideo -pix_fmt rgba -s WxH -r fps` → `<scene>.webm` (`libvpx-vp9 -crf 38 -b:v 0`, scaled to 1280 wide), `<scene>.mp4` (`libopenh264`, `-pix_fmt yuv420p`, bitrate tuned to stay under ~2 MB), `<scene>.jpg` poster (frame at 70%); scenes with only PNG shots are converted to `.webp`. Writes `website/media/showcase/showcase.json` in the Task 3 format, and deletes the temp data dir.
